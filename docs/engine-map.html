There is no camera object. The database holds 1611 structs and not one is a Camera or a Frustum — those names return zero hits as types, and no frustum-culling function exists under any spelling. The engine's entire camera is a single 240-byte global of flat state plus a dirty-flag bitmask, drained to the GPU at exactly one place.

That is the good news for a VR port: there is one choke point to intercept, not a class hierarchy to subvert.

The call path

app @ 0x1405833E0

The game logic lives in per-title DLLs (tomb4/5/6). They never call the renderer directly — they call through a function-pointer table, the app struct. vidInit installs roughly forty vid_* entries into it and init_ogl installs forty-seven ogl_* entries. Every renderer entry point in this map has zero direct call sites in the exe; each is address-taken exactly once, at its install site.

mProj is mat4[2]: slot 0 is orthographic, slot 1 is perspective. Every perspective setter writes slot 1; vid_setOrtho3D copies slot 0 into slot 1 and repoints. Which one is live is decided per pass — see vid_setPass.

Address-space note

Globals sit at 0x14Exxxxxx while the file on disk is only 1.6 MB. That is not a bad symbol: .data genuinely spans 0x140167000–0x14E9BDBDF, a 232 MB mostly zero-filled section. Every one of these is a legitimate image-base + RVA and safe to compute at runtime.

Correction to the working notes

Earlier notes recorded joints as 0x1000000. It is 0x40000 (bit 18). The check: 0xff07bf sets exactly bits {0–5, 7, 8–10, 16–23}, and every entry above falls inside it. Bit 24 is not in that mask at all, so it cannot have been a real flag.

validate_draw

0x140011CC0 1967 bytes

The single point where every matrix reaches the GPU. It binds the program if the shader changed, sets sampler assignments through a 202-case switch, drains the dirty flags, rebinds the seven texture units, then reconciles depth, blend and cull.

The trap

The view matrix does not go up through glUniformMatrix4fv. Projection and shadow do; view and model go up as four vec4s through glUniform4fv. Hooking glUniformMatrix4fv — the obvious move — catches projection and misses view entirely.

// the upload block, condensed
if ((consts & 1)     && uid[0] >= 0) glUniformMatrix4fv(uid[0], 1, GL_FALSE, &proj->e00);
if ((consts & 2)     && uid[1] >= 0) glUniform4fv(uid[1], 4, &view->e00);   // <-- not Matrix4fv
if ((consts & 4)     && uid[2] >= 0) glUniformMatrix4fv(uid[2], 6, GL_FALSE, &shadow->e00);
if ((consts & 0x10000) && uid[5] >= 0) glUniform4fv(uid[5], 4, &model->e00);  // <-- not Matrix4fv
...
vid_state.consts = 0;   // mask is consumed

glUniformMatrix4fv is itself a data variable at 0x14E525C68, not a function, so calls to it are indirect. It has exactly three references: a write in init_ogl that resolves it, and the two call sites inside validate_draw.

Because the mask is zeroed at the end, anything that raises consts before the original runs will be uploaded and then cleared — which is what makes per-draw matrix substitution practical.

vid_setPass

0x14000C4C0 2944 bytes · app.setPass

void vid_setPass(int shader, float *params, int cull, int blend). This translates “draw this kind of thing” into a full vid_state configuration. Its 202-case switch sets depth state, the seven texture slots, and — the part that matters most — which projection matrix the pass uses.

So vid_setPass is the world-space / screen-space switch. That makes it the natural gate for “does this pass get per-eye matrices?” — the ortho group is exactly the flat 2D layer you want to leave alone.

Two subtleties that will bite

  • Sticky state. Cases 0x3F, 0x40, 0x48, 0xC0, 0xC1, 0xC4–0xC7 never assign proj at all and inherit the previous pass's pointer. A static table of shader ids would classify these wrong — read vid_state.proj after the call instead.
  • The proj dirty bit is a pointer comparison. The tail does if (vid_state_prev.proj != vid_state.proj) consts |= 1. Writing new contents into the same mProj[1] raises nothing. That is exactly why every projection setter sets consts |= 1 itself.
Robustness gap

vid_state.shader is assigned before the range check. A shader id above 201 hits if (0xc9 < id) goto tail, skipping all configuration — then validate_draw indexes shaders[id] out of bounds. No clamp, no assert, no log. Worth a guard if you ever synthesise pass ids.

vid_setViewMatrix

0x14000B960

Takes a 3×4 integer matrix — twelve ints, row-major — and writes two different globals. Rotation is classic Tomb Raider fixed point where 16384 = 1.0; translation is passed through raw in world units.

// mView_packed @ 0x14E51CB30, as float[16]
[ 0..3 ]  =  ( m0,  m1,  m2,  m3 )   // row 0, translation X raw in .w
[ 4..7 ]  =  ( m4,  m5,  m6,  m7 )   // row 1, translation Y
[ 8..11]  =  (-m8, -m9, -m10, m11)   // row 2 NEGATED, translation Z
[12..15]  =  ( 1,   0,   ...    )    // unused by the shader
// rotation terms scaled by 1/16384; translation NOT scaled

Three things follow. The Z row is negated — that is the handedness flip onto GL's −Z forward. The layout is row-major 3×4, one row per vec4, which is why it is uploaded with glUniform4fv and needs no transpose flag. And TR world space is Y-down, which the projection compensates for — see next.

Projection & the VR levers

0x140012840 · 0x14000B8D0 
void ogl_setPerspAngles(float tanX, float tanY, float zNear, float zFar) {
    vid_state.consts |= 1;
    mProj[1].e00 =  1.0f / tanX;
    mProj[1].e11 = -1.0f / tanY;            // <-- engine renders Y-flipped
    mProj[1].e02 =  0.0f;  mProj[1].e12 = 0.0f;   // symmetric: no shear
    mProj[1].e22 = (zNear + zFar) / (zNear - zFar);
    mProj[1].e23 = (2.0f * zFar * zNear) / (zNear - zFar);
    mProj[1].e32 = -1.0f;  mProj[1].e33 = 0.0f;
}

void vid_setPerspOffset(float x, float y) {
    vid_state.consts |= 1;
    mProj[1].e02 = x;   // (r+l)/(r-l)
    mProj[1].e12 = y;   // (t+b)/(t-b)
}

Field naming follows the PDB: eRC is row R, column C, at float index C*4 + R. So e32 lands at index 11 (the −1) and e23 at index 14 — exactly glFrustum's column-major layout, with one deviation: e11 is negative. The engine renders Y-flipped throughout, and ogl_setScissor agrees, flipping Y against gTargetHeight.

vid_setPerspOffset does nothing but write the two frustum shear terms. That is precisely the asymmetric-frustum lever a per-eye VR projection needs — already exposed as an API entry point, already setting its own dirty bit.

A useful consistency check. Feed a symmetric frustum (l=−k, r=k, t=−j, b=j) through the standard asymmetric formula and negate Y, and you get e00 = 1/k, e11 = −1/j, zero shear, and identical depth terms — byte for byte what ogl_setPerspAngles writes. A correct per-eye projection therefore differs from the engine's own only by the asymmetry VR asks for.

ogl_setRenderTarget

0x140013C30 713 bytes · app+0x178

Three phases: latch the request into the 24-byte ogl_rt global; invalidate all seven texture units by stamping vid_state_prev.tex[i] = 0xFFFFFFFF so a texture still bound as a sampler cannot also be a target; then bind.

Every render target is a layered 2D array texture. The code uses glFramebufferTextureLayer with GL_TEXTURE_2D_ARRAY throughout and never glFramebufferTexture2D; color_index is the array layer. Per-eye targets would need no new plumbing.

Four things that will surprise you

One FBO. FBO_custom at 0x14E9ADF28 is a single global. Every offscreen pass re-attaches colour and depth and runs a full glCheckFramebufferStatus on every target change.

That status is discarded. No branch, no log. An incomplete FBO from a bad layer index fails silently.

No stencil anywhere. GL_DEPTH_ATTACHMENT only, never GL_DEPTH_STENCIL_ATTACHMENT.

ogl_rt is a latch, not a stack. Written only here, read only by ogl_texCopy. Nested target changes do not restore — the inner restore clobbers the outer's saved state.

There is also an asymmetry worth knowing: returning to the backbuffer sets consts |= 4 (shadow matrices), but switching between offscreen targets does not. Reading ogl_rt.color_id == 0 && ogl_rt.depth_id == 0 is a reliable test for “currently targeting the backbuffer”.

The shader-side uniform interface

uniform mat4 uProjMatrix;        // uid[0]  glUniformMatrix4fv
uniform vec4 uViewMatrix[4];     // uid[1]  glUniform4fv
uniform mat4 uShadowMatrix[6];   // uid[2]  glUniformMatrix4fv
uniform vec4 uModelMatrix[4];    // uid[5]  glUniform4fv
uniform vec4 uLightPos[8], uLightCol[8], uLightDir[8];
uniform vec4 uJoints[72 * 3];

View and model being vec4[4] is by design in the GLSL, not a decompiler artifact — that settles it. Samplers are all array-textured (sampler2DArray, sampler2DArrayShadow), consistent with the layered render targets.

Three landmines for an injector

GL 3.2 Core is the binding constraint. GL_OVR_multiview2 would need the extension declared in all 404 shader sources plus driver support on a 3.2 core context. Drawing the scene twice needs zero shader changes, because uViewMatrix is already a plain vec4[4] you can overwrite.

FBO_default is latched from whatever is bound at init. If a VR runtime binds its own framebuffer before init_ogl runs, every “return to backbuffer” goes somewhere unexpected. Equally, overwriting that global redirects the whole engine without hooking anything.

Scissor test is enabled globally at init. Any per-eye viewport must update the scissor box too, or the second eye is clipped away.

init_ogl always returns 1. There is no failure path: if wglCreateContext fails, hRC is NULL, wglMakeCurrent fails silently, and every later GL call is a no-op.

Where to hook for stereo

the short answer

Two functions do the VR work; three more are unavoidable plumbing.

FunctionAddressPrologueRole
vid_setPass0x14000C4C010 BClassify pass: world-space vs 2D
validate_draw0x140011CC06 BInject per-eye projection + view
ogl_draw0x140012BD05 BDuplicate the draw per eye
ogl_drawVB0x140012CF05 BSame, second draw path
ogl_present0x1400126006 BFrame boundary: submit, mirror, pose

Why the split. validate_draw is the right place to substitute matrices — it is the only place they reach the GPU — but it cannot issue a draw. Its two callers do that immediately after it returns:

// ogl_draw, tail
validate_draw();
glDrawElements((strip != 0) + 4, count, type, offset);

So per-eye duplication has to sit one level up. Each draw is issued twice into the two halves of one double-wide target with different matrices and a different viewport; the scene is never re-run.

All five prologues are position-independent, so a five-byte relative jump with a hand-counted stolen-byte constant is enough — no length disassembler required. Verify the bytes before patching and a game update degrades to “VR did not start” rather than a corrupted instruction stream.

Worth noting: the binary carries Control Flow Guard metadata, but both _guard_check_icall and _guard_dispatch_icall resolve to the nop variants, so CFG is not enforced. Patching the app vtable would also work — inline hooks are simply safe either way.

Errata & open questions

what to re-check

Corrected while consolidating

  • joints dirty bit is 0x40000, not 0x1000000. Confirmed against the 0xff07bf shader-switch mask.
  • The 0x14Exxxxxx globals are real. Earlier suspicion that they were bad PDB placements was wrong — .data really is 232 MB.
  • gTargetWidth at 0x143298680 sits 44 MB from gTargetHeight at 0x140698678 despite being written as a pair. Both are referenced by two functions each (appGetWidth/appGetHeight and ogl_setRenderTarget), so the layout is odd but the symbols are real.

Still open

  • The frame graph. How the post-processing chain composites into the backbuffer has not been traced end to end. This is the part of a VR port most likely to need live iteration.
  • mView (rotation-only, 0x14E51C8C0) has a consumer separate from mView_packed that has not been chased down.
  • Culling. No frustum-culling function exists in the exe under any spelling — only vid_setInverseCullingFlag at 0x14000D730, which flips winding. Culling most likely lives in the per-game DLLs.
  • CameraSide at 0x14015AAD0 is the only global with “Camera” in its name: cubemap face matrices read by ogl_getCubemapMatrix. The “Camera Systems Programmers” hit at 0x14007A598 is a credits string.
